# AGENTS.md — instructions for AI coding agents working on Company in a Box

## Ground rules

1. **Ponytail mode applies: smallest complete change wins.** No speculative abstractions, no "for later" code. Skip features nobody asked for and say so in one line when you do.
2. This is a **pnpm + Turborepo workspace** on Node 22+. Never edit `pnpm-lock.yaml` by hand. Run `pnpm install` from the repo root after adding dependencies.
3. Type safety: `pnpm typecheck` must pass before you claim done. Tests: `pnpm test`.
4. The auth bundle is **prebuilt with esbuild**; TypeScript cannot import it directly (see below). A core/auth source change without `pnpm auth:build` is an unfinished change.

## Build & verify loop

```bash
pnpm install        # after dependency changes
pnpm typecheck      # tsc --noEmit workspace-wide (turbo)
pnpm test           # vitest workspace-wide
pnpm build          # turbo build
pnpm auth:build     # REQUIRED after packages/core/src/auth/** changes
```

The `auth:build` script bundles `packages/core/src/auth/index.ts` →
`packages/core/dist/auth-handler.mjs` with esbuild (externals: `better-auth`,
`drizzle-orm`, `@libsql/client`, `ulid`). The Vite dev middleware imports that
dist file, not the TS sources. If it fails to load you will see
`[better-auth] handler failed to load — did you build core?` in the Vite log.

## Auth architecture (dev)

- The auth server is `better-auth` in `packages/core/src/auth/index.ts`.
- In dev, `packages/frontend/vite.config.ts` mounts it at `/api/auth/*`
  (middleware runs **before** Vite's `/api` proxy to :3100).
- `GET /api/auth/config` returns `{google, apple}` booleans driven by env;
  login/register pages hide unconfigured provider buttons.
- Providers are registered **only when credentials exist** — unconfigured
  providers intentionally 404 with provider-not-found rather than 500-ing.
- Apple `clientSecret` is a dynamically generated ES256 JWT from the `.p8` key
  (180-day validity), generated by `generateAppleClientSecret()`.

### Environment variables (all optional-safe)

Loaded from `packages/frontend/.env.local` (git-ignored; `.gitignore` covers `.env*` and `*.p8`).
`vite.config.ts` loads all keys (empty-prefix `loadEnv`) and forwards the auth
set into `process.env` before importing the handler.

| Var | Purpose |
|---|---|
| `DATABASE_URL`, `DATABASE_AUTH_TOKEN` | libSQL/Turso connection; local SQLite when unset |
| `AUTH_SECRET` | better-auth secret (dev fallback exists — set before any real deployment) |
| `AUTH_BASE_URL` | better-auth base (default `http://localhost:5173`). Redirect URI for Google = `<base>/api/auth/callback/google` exactly |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | Google sign-in |
| `APPLE_CLIENT_ID`, `APPLE_TEAM_ID`, `APPLE_KEY_ID`, `APPLE_PRIVATE_KEY` | Apple sign-in (secret auto-generated) |
| `APPLE_APP_BUNDLE_IDENTIFIER` | optional Apple app-id scope |

Secrets never go in chat, tickets, or the repo. See `.gitignore` — `.env*` and `*.p8` are ignored. Report real exit codes; never claim tests passed that didn't run.

## Code layout conventions

- Package names: `@company-in-a-box/<pkg>`. Alias `@` → `packages/frontend/src`.
- Workspace aliases exist for cross-package imports: `@company-in-a-box/<pkg>` maps to `packages/<pkg>/src`.
- Tests live in `packages/<pkg>/tests` via vitest. Lint/format with `oxlint` / `oxfmt`.
- Server ports: frontend dev 5173, API target 3100 (Vite proxy for non-auth endpoints).

## Git hygiene

- Commit with clear messages; keep diffs scoped to the task.
- Never commit: `.env*`, `*.p8`, `node_modules`, `dist`, `.DS_Store` (all ignored).
- This directory sits under a parent `$HOME` git repo; the nested repo here is the authoritative one — commits belong here, not in `$HOME`.

## Known limits (do not rediscover these)

- The Google Cloud Console OAuth client-create screen does not render in the
  in-session Electron browser; client creation must be done in a real browser.
  Everything downstream of that is automated.
- Google only issues refresh tokens on first consent: `accessType: "offline"` +
  `prompt: "select_account consent"` are already set — don't remove them.
